# Support Triage Assistant — project charter

This is a fictional release-test document. It contains no customer data or credentials.

Sponsor: Maya Chen. Project manager: Alex Rivera. Engineering lead: Sam Lee.
Stage: Pilot. Risk tier: 2. No committee approval has been granted.

The assistant proposes a category and priority for incoming support requests and drafts an initial response. A support specialist reviews every suggestion before anything is sent. It must never send messages or change account settings automatically.

Targets: reduce manual effort by 20% and time to first reviewed response by 35%. These are goals, not observed benefits. Baseline: 12 minutes of handling effort and 40 minutes to first response per request.

Milestone 1: Ticket classification, planned for October 2026, currently planned. Potential base impact: 8% effort and 15% time; stretch impact: 12% effort and 20% time. Evaluation metric: classification accuracy, base gate 90%, stretch 95%. No measurements have been recorded.

Milestone 2: Reviewed response drafts, planned for November 2026, currently planned. Base impact: 12% effort and 20% time; stretch: 16% effort and 25% time. Evaluation metric: grounded response rate, base 95%, stretch 98%. No measurements have been recorded.

Governance: privacy assessment missing, owner Maya Chen; human-review operating procedure in review, owner Alex Rivera; rollback runbook missing, owner Sam Lee.

Release: Support Pilot, November 2026. Require both milestones to pass gates, an approved privacy assessment, and a manually confirmed support-team training session. No deployment is claimed. No repository has been selected.
